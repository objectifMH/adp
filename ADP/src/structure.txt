Explications des dossiers :
core/ :
Contient les services, intercepteurs et guards qui sont utilisés globalement dans l'application. Ces éléments sont généralement des singletons (instanciés une seule fois).

shared/ :
Contient les composants, directives, pipes et modèles réutilisables dans toute l'application. Ce module est importé dans les autres modules fonctionnels.

features/ :
Organisé par fonctionnalité (ex: home, product, cart). Chaque fonctionnalité a son propre module, composants et services. Cela permet une séparation claire des responsabilités et facilite le lazy loading.

assets/ :
Contient les ressources statiques comme les images, polices, etc. Vous pouvez également y ajouter un dossier styles/ pour les variables SCSS globales, mixins, etc.

environments/ :
Contient les configurations spécifiques à chaque environnement (développement, production, etc.).

styles.scss :
Le fichier SCSS global qui importe les styles communs à toute l'application.

Bonnes pratiques :
Lazy Loading : Utilisez le lazy loading pour charger les modules fonctionnels (features/) uniquement lorsqu'ils sont nécessaires. Cela améliore les performances de l'application.

SCSS modulaire : Organisez vos fichiers SCSS en les associant à leurs composants. Utilisez des fichiers SCSS globaux pour les variables, mixins et styles communs.

Services par fonctionnalité : Si un service est spécifique à une fonctionnalité, placez-le dans le dossier services/ de cette fonctionnalité. Sinon, mettez-le dans core/.

Interfaces et modèles : Placez les interfaces et classes de modèle dans le dossier shared/models/ pour les réutiliser dans toute l'application.
